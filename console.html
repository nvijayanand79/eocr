Close execution

eOCR closes an execution itself when ACE's callback arrives. Close by hand only when the callback never came: the console asks the Status API first, and if the job is terminal it retrieves the result (reconciliation); otherwise it records the execution as abandoned.

How to read the console

Execution
One eOCR run for one loan: its own folder loanId=…/correlationId=…/ in the intake bucket. Identified by its correlationId.
ACE job (aceJobId)
The number ACE gives the execution when it accepts it. Every status and callback refers to it.
Control file
The JSON next to the documents that tells ACE the loan data, the document list and whether to extract fields.
ACE stage / state
Where ACE is (PRECHECK, CLASSIFICATION, EXTRACTION…) and what that step is doing (RUNNING, HITL_PENDING…), read from ACE's Status API.
HITL review
ACE paused for a person to confirm loan data it could not match. The console can act as that reviewer.
Callback
ACE calling eOCR back with the final outcome. ACE retries until eOCR answers 200.
Result file (batchPath)
The *Response.json ACE writes with the documents it found and the fields it extracted.
Outcomes
0 COMPLETED · 1000 PRECHECK_FAILED (bad or unreadable files) · 2000 VALIDATION_FAILED (loan data does not match the NOTE) · 3000 PROCESSING_FAILED (ACE error).
Spec compliance
Every ACE answer is checked against the integration specification; any deviation is listed on the execution.
Where the data comes from
Progress, outcome and result all come from ACE (Status API, callback, output bucket). The console only records them, in S3.
